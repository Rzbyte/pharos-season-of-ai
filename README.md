# pharos-season-of-ai
My builds for the Pharos Season of AI Agent Arena using Chain MCP, Developer Docs MCP, and SkillEngine.

**Live:** https://pharos-agent-lab.vercel.app · **Status:** [PROGRAM_STATUS.md](PROGRAM_STATUS.md)

| Task | What it is |
|---|---|
| [01 · Read Contract State](tasks/01-read-contract-state) | A CLI and a web demo that read the Circle USDC Contract on Pharos Mainnet through Pharos Chain MCP, pinned to one block; the web demo adds the Pharos Inspector, with an optional plain-language explanation of a result |
| [02 · Event / Log Monitor](tasks/02-event-log-monitor) | A CLI and a web monitor of Circle USDC Transfer events on Pharos Mainnet through Pharos Chain MCP `get_logs`, each event shown once |
| [03 · Docs MCP Onboarding](tasks/03-docs-mcp-onboarding) | The onboarding evidence with the Pharos Developer Docs MCP, as a short case-study page built from `evidence.json` |
| [04 · Doc-Search CLI](tasks/04-doc-search-cli) | `pharos-docs`: a question in, a short answer from the official Pharos docs through the Pharos Developer Docs MCP (`askQuestion`) with its source pages out, or a plain no-answer; a docs search page runs the same search |
| [05 · Threshold Guardian](tasks/05-threshold-guardian) | Six on-chain conditions read at one block through Pharos Chain MCP; a USDC payout fires only when all hold, simulated first; on Atlantic it re-checks, signs locally and broadcasts through Chain MCP |
| [08 · Dry-Run Executor](tasks/08-dry-run-executor) | A transfer, approval or contract call simulated at one block through Pharos Chain MCP before it is sent: the verdict, before → after for every balance it changes, the gas and fee, and warnings; on Atlantic it submits and checks the receipt against the prediction |
| [09 · Trend Watcher](tasks/09-trend-watcher) | One on-chain value read through Pharos Chain MCP on each run and kept in a store across runs; it acts only when the observations show a trend (falling, rising, a % change or a threshold held), once per trend, with its action dry-run first; the proofs chain run to run |
| [11 · Policy Gatekeeper](tasks/11-policy-gatekeeper) | A payment request checked against a written policy at one block through Pharos Chain MCP before anything is signed: per-action and window spend limits (the window from the sender's own Transfer logs), asset and counterparty allowlists, allowed hours at the block's time, a gas cap and a dry run; every failing rule named |
| [13 · Docs MCP + Chain MCP Agent](tasks/13-docs-chain-agent) | A question about a Pharos contract answered from the official docs, then checked and called on chain: the Pharos Developer Docs MCP answers (`askQuestion`) and the pages it cites are read (`getPage`) for the contract's address, network and functions; Pharos Chain MCP reads its code, calls the functions the docs give, and reads a token's symbol, name, decimals and supply at one block; the chain's own name is set beside the docs' and the Skill Engine's, and the verdict says whether the chain agrees with the docs; each step with its source |
| [17 · Natural-Language Payment Agent](tasks/17-natural-language-payment) | A payment request in plain words ("Pay alice 25 USDC and send 0.01 PROS to bob for lunch") read by a small grammar, every word of it: recipients by address or an address book, "each" and "split", a note, a sender; anything it cannot read is refused with the words it did not read. Each payment is dry-run through Pharos Chain MCP at one block (Task 08), the totals are checked against what the sender holds, and the flow comes as the transactions to sign in nonce order with the Pharos Skill Engine's `cast send`; on Atlantic the CLI sends them in order and checks each receipt |
| [18 · Recurring Payment Agent](tasks/18-recurring-payment) | Repeating payments (rent, payroll, subscriptions) from a schedule a line ("Rent: 25 USDC to 0x…, monthly on the 1st"), read by a small grammar: daily, weekly, monthly or yearly, or every N of them from a day, until a day. Each run reads the chain's UTC day: every due day since the start not recorded as paid is owed, the oldest taken within limits and prepared as Task 17's flow through Pharos Chain MCP (Task 08's dry runs, the totals, the transactions to sign, the Pharos Skill Engine's `cast send`). The CLI's store records each payment paid, so a missed run is caught up and nothing is paid twice; a pending send waits for its receipt; on Atlantic it sends; runs verify as one history |
| [19 · Invoice-to-Payment Agent](tasks/19-invoice-to-payment) | An invoice pasted as text, or an EIP-681 payment link, read by rules into the payment it asks for: every figure checked against the others (lines, subtotal, discount, tax, total, paid, amount due, the link) or the invoice refused, saying which disagree; a currency, another network or an address failing its checksum refused too. The payee is checked against your payees and the payer's last 2,000 blocks of transfers through Pharos Chain MCP (`get_logs`): a changed address, a new payee, the same amount paid already, or a lookalike holds the payment. Then Task 17's flow prepares it: Task 08's dry run, the transaction to sign, the Pharos Skill Engine's `cast send` and an EIP-681 link; on Atlantic the CLI sends it only when nothing is held |
| [20 · X402 Paywalled API](tasks/20-x402-paywalled-api) | An API that charges per request with x402 on Pharos, all three parties on the official x402 packages: `GET /data` answers 402 with its terms in USDC; a client signs an EIP-3009 authorization for exactly them, never above its cap; a facilitator whose every chain read and write goes through Pharos Chain MCP verifies it (the transfer simulated on chain) and settles it (`transferWithAuthorization` sent, the receipt's Transfer checked), and only then is the data released. On Atlantic the CLI pays and settles, and serves the API over HTTP for any x402 client; on Pharos Mainnet, where the hosted Chain MCP is read-only, it runs up to the facilitator's check on chain |
| [21 · X402 Agent Buyer](tasks/21-x402-agent-buyer) | An agent with a job and a USDC budget that buys what the job needs from x402-paywalled APIs, and no more: it asks each price for free (the 402), plans within the budget, and pays with x402's own client, each payment capped at what is left. The job is a planned transfer to check before it is sent: it buys Task 25's risk check and Task 08's dry run from Task 20's API, both answered through Pharos Chain MCP, stops early when the check says do not send, and finishes with the verdict, the ledger and the transaction to sign. On Atlantic it pays and settles; on Pharos Mainnet, where nothing settles, its first payment is refused on chain and the job is not done |
| [22 · On-Chain Alert Bot](tasks/22-on-chain-alert-bot) | An alert bot on Pharos Mainnet through Pharos Chain MCP, run after run: transfers of a token (by size, sender and recipient) from `get_logs`, each alerted once from a cursor kept between runs, and conditions on balances, view calls and gas, alerted when they start and when they stop; the CLI posts each alert to a webhook and retries what it refused; the proofs chain run to run |
| [23 · Whale-Watching Agent](tasks/23-whale-watching-agent) | Chosen addresses tracked on Pharos Mainnet through Pharos Chain MCP, run after run: holdings, nonce and code read at one block, their token transfers from `get_logs` (two OR-topic queries a page), and the significant moves surfaced once (transfers over an amount, native balance changes over another); the rest summed per address; the proofs chain run to run |
| [24 · Gas Fee Optimizer](tasks/24-gas-fee-optimizer) | The base fee observed through Pharos Chain MCP, run after run, and one transaction timed against it: send now when the fee is at or below a target (a percentile of the observations, or a fixed fee) or past a deadline, else wait; fee settings capped at the target, and the cost now, at the target and at most; on Atlantic it sends once, and the proof checks the signed fee cap |
| [25 · Wallet Risk Checker](tasks/25-wallet-risk-checker) | The address a Pharos transaction goes to, checked through Pharos Chain MCP before it is sent: what it is (wallet, contract, or EIP-7702 delegate), its nonce and balance, and its recent transfers with the sender from `get_logs`; it flags address poisoning (a lookalike of a real partner, transfers of nothing), approvals to wallets, unlimited approvals, tokens sent to a token contract, never-used addresses and a transaction that would fail, each signal with its tool, and says do not send, check first or looks fine |
| [26 · Audit-Log Agent](tasks/26-audit-log-agent) | What a Pharos address did over a selected period (the last hours, two times or two blocks), read through Pharos Chain MCP and written in plain sentences: the period placed in blocks from the chain's own block times, the address read just before it and at its end, its logs over every official token in two queries a page; transactions sent, flows and counterparties, approvals, transfers of nothing, balances reconciled with the logs, and a timeline; no language model, so each report replays as a proof |
| [27 · dApp Support Agent](tasks/27-dapp-support-agent) | Why a Pharos transaction failed, on request, through Pharos Chain MCP: its receipt, its call replayed before its block for the revert, decoded in plain language (Error, Panic codes, OpenZeppelin's errors with token amounts), the sender's balance, out of gas or something earlier in its block, each finding with its tool, and a fix; a transaction described instead is explained as it would fail now; no language model, so each answer replays as a proof |
| [28 · Weekly Digest Agent](tasks/28-weekly-digest-agent) | A periodic summary of a token's or a wallet's activity on Pharos, through Pharos Chain MCP: UTC hours, days or weeks, each period placed in blocks from the chain's own block times, its logs read once (a token's every transfer, or a wallet's transfers and approvals), in sentences: transfers, volume, senders and recipients, the largest, who moved the most, mints and burns, each period against the one before and its busiest part named; with a store, a scheduled run digests each period once; no state read in the past |
| [29 · Doc-Grounded Builder Agent](tasks/29-doc-grounded-builder) | How to do something on Pharos, answered from the official docs through the Pharos Developer Docs MCP, then prepared: the action the question asks for (sending PROS or an official token, approving a spender, wrapping PROS, a balance), its chain ID, RPC URL, token address and function set beside the Pharos Skill Engine's and the docs', Task 08's dry run through Pharos Chain MCP, and the Skill Engine's `cast` commands with its gas rule; on Atlantic the CLI signs and sends it and checks the receipt |

[`agent/`](agent) is the agent runtime behind Tasks 05 onward: one package that gains a capability per
task. [`lab/`](lab) is the landing page that indexes the tasks, and [`shared/ui/`](shared/ui) is the
design system every page shares (`node shared/ui/sync.mjs` copies it into each deployment).

The whole lab deploys as one site from the repository root: the lab at `/` and each task at
`/tasks/NN` ([`site/`](site) explains how).
