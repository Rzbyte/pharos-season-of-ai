    The example is the address that moved the most USDC in Task 02's live proof, a public address picked from real activity, not known to be anyone in particular. The page reads at most 20,000 blocks: a longer period is cut to its newest 20,000, and the report says so. The CLI reads up to 100,000. Nothing is signed or sent from this page.

    Proof & technical details

    How it reads

    1. 1get_blockThe period in blocks: the first block after its start and the last at its end, found by interpolating on the chain's own block times
    2. 2get_balance · get_transaction_count · eth_callThe address at the block before the period and at its end: its PROS, its nonce (the transactions it sent) and each official token
    3. 3get_logsEvery official token at once, 1,000 blocks a page, two queries a page: Transfer, Approval and wrapping logs from the address, then Transfer logs to it
    4. 4reportFlows and counterparties, approvals, transfers of nothing, and each balance reconciled with the logs, written as sentences from those values; no language model

    Run it yourself
    
        
    cd agent && npm ci
node dist/src/cli.js audit 0x… --hours 24 --proof report.json
node dist/src/cli.js audit 0x… --since 2026-10-17T00:00 --until 2026-10-17T12:00
node dist/src/cli.js verify report.json
    
        
    The verifier replays the recorded Chain MCP answers through the same code: the same calls give exactly the recorded figures and sentences, every state read at the block before the period or at its end, and every get_logs call inside the blocks it says it read. The CLI paces its calls under the hosted endpoint's 120 a minute.
