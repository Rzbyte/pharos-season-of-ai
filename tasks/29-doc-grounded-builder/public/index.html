            How it answers

            1. 1askQuestionThe question, to the Pharos Developer Docs MCP. An answer the docs say they do not cover, or with no page behind it, is not acted on: nothing the docs do not answer is prepared
            2. 2the questionThe action it asks for, by its words: sending PROS or an official token, approving a spender, wrapping PROS, or a balance. Its amount, token and addresses come from the question, else the example's
            3. 3getPageThe chain ID, RPC URL, token address and function, each set beside the Pharos Skill Engine's. A token's address is looked up on the pages the answer cites, at most two
            4. 4eth_call · estimate_gasTask 08's dry run at one block: the state it changes, the call simulated from the sender, the gas and the fee, the outcome. A balance is read instead
            5. 5castThe Skill Engine's command templates for it, filled in, with its gas rule (the estimate × 1.2, times the gas price). Nothing is sent from here; the CLI sends on Atlantic with a key

            Run it yourself
            
        
            cd agent && npm ci
node dist/src/cli.js howto "How do I send USDC to another wallet on Pharos Mainnet?" --proof answer.json
node dist/src/cli.js howto "How do I send 1 USDC to 0x…?" --network atlantic-testnet --execute
node dist/src/cli.js verify answer.json
            
        
            The verifier replays both recorded transcripts, the Developer Docs MCP's and the Chain MCP's, through the same code: the same calls give exactly the recorded action, comparisons, dry run and verdict; a sent transaction must be exactly the dry-run one, signed by its sender. The docs' answer is the Developer Docs MCP's; the agent adds no language model: the action comes from the question's words, and the commands from the Skill Engine's templates.
