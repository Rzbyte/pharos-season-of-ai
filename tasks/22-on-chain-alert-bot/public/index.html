The bot's memory, the last block it scanned and which conditions held, is kept in this browser with the alerts; each run sends it, and the agent reads only what is new through Chain MCP. Alerts are shown here; the CLI also posts them to a webhook. Nothing is signed or sent from this page.

      Proof & technical details

      How it watches

      1. 1get_chain_infoConfirms Pharos Mainnet, chain 1672
      2. 2get_block_number · get_blockPins the newest block
      3. 3get_logsUSDC's Transfer logs from the block after the last run's to the pinned one, at most 1,000 blocks a call. A first run looks back 1,000 blocks. Each transfer of the smallest amount or more is one alert, and is never reported again
      4. 4eth_call · get_gas_priceThe holder's balance, paused() and the gas price, read at the pinned block and compared with the last run: a condition alerts when it starts to hold and when it stops
      5. 5deliverHere, the alerts join the list in this browser. The CLI prints them and posts each to a webhook, keeping any the webhook refused for the next run

      Run it yourself
      
        
      cd agent && npm ci
node dist/src/cli.js alert --store alerts.json --proof run-1.json
node dist/src/cli.js alert --store alerts.json --webhook https://… --proof run-2.json
node dist/src/cli.js verify run-1.json run-2.json
      
        
      Each run reads only the blocks after the last one and keeps its memory in the store file. With --webhook, each alert is posted as JSON, its line in text and content for Slack or Discord. The verifier replays each run's recorded Chain MCP answers through the same code, and checks the runs as one history: each must start from exactly the store the run before it left. A bot is a JSON file of up to 12 rules: transfers of any token, filtered by sender, recipient and size, and conditions on balances, view calls and the gas price.
