18Recurring Payment Agent

Pay on schedule

What fell due, caught up and dry-run via Pharos Chain MCP, each paid once

One payment a line: "Name: amount asset to 0x…, rule". Daily, weekly on a day, monthly on a day, yearly on a date, or every N of them "from" a day; "until" a day ends it. Ctrl+Enter prepares it.

The first day counted. Empty: the first of this month, at the block's time.

Pays every line. Empty: the example address.

          How it runs
          
          
            
            
          1. 1readThe schedule, a payment a line, by a small grammar: who is paid, how much of PROS or an official token, how often, from and until which day. A line not read whole is refused, saying which part
            2. 
            
          2. 2get_blockThe day, from the chain: the pinned block's UTC day. Every day a payment fell due since the start, and is not recorded as paid, is owed; a run takes the oldest, at most 3 of one payment and a few in all
            3. 
            
          3. 3eth_call · estimate_gasThe payments taken, as Task 17 prepares a flow: the payer's nonce, Task 08's dry run of each at the same block, the totals against what the payer holds
            4. 
            
          4. 4preparedEach as the transaction a wallet signs, in nonce order, and as the Pharos Skill Engine's cast send
            5. 
            
          5. 5the storeThe CLI keeps what is paid: on Atlantic, with a key, each payment is sent, checked against its receipt and recorded, so the next run never pays it again; one sent but not yet in a block waits for its receipt
            6.

          Run it yourself
          
        
          cd agent && npm ci
printf 'Rent: 25 USDC to 0x…, monthly on the 1st\n' > schedule.txt
node dist/src/cli.js recurring schedule.txt --store store.json --since 2026-10-01 --proof run-1.json
node dist/src/cli.js recurring schedule.txt --store store.json --proof run-2.json
node dist/src/cli.js verify run-1.json run-2.json
# from cron, on Atlantic, with your testnet key:
PRIVATE_KEY=0x... node dist/src/cli.js recurring schedule.txt --store atlantic.json --network atlantic-testnet --execute
          
        
          The verifier reads the schedule again and replays the recorded Chain MCP answers through the same code, from the store each run started with: the same calls give exactly the recorded owed payments, flow, store and verdict, and each sent payment must be exactly its dry-run one, signed by the payer. Several runs verified together must form one history, each from the store the last one left, no payment recorded twice.
