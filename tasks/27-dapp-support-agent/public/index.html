    How it answers

    1. 1get_transaction · get_transaction_receiptThe transaction and how it ended: succeeded, failed, pending, or unknown to the network
    2. 2eth_callWhen it failed: its call replayed at the block before its own, which returns the revert data
    3. 3decodeThe revert in plain language: Error(string), Panic codes, and OpenZeppelin's errors, token amounts in the token's units
    4. 4get_code · eth_callIs the target a contract, and for a token transfer, what the sender held. All the gas used means it ran out of gas; a replay that succeeds means something earlier in its block made it fail
    5. 5dry runA transaction described instead of sent is dry-run at the newest block (Task 08) and explained the same way
