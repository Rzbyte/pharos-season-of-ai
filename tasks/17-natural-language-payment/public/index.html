        How it prepares
        
          
          
            
        1. 1readThe request, by a small grammar, every word of it: pay, send, transfer, give or split; an amount with its asset; recipients by address or the address book's names; "each", "split", "for" a note, "from" a sender. A request not read whole is refused, with the words that were not
          2. 
            
        2. 2get_transaction_countThe sender's next nonce at one block: the payments take it and the ones after, in order
          3. 
            
        3. 3eth_call · estimate_gasEach payment dry-run at the same block (Task 08): the balances it changes, the call from the sender, the gas and the fee
          4. 
            
        4. 4the flowEach asset in all against what the sender holds, PROS with every payment's maximum fee on top: the dry runs each start from the same balances, so together they must fit in them
          5. 
            
        5. 5preparedEach payment as the transaction a wallet signs, nonce by nonce, and as the Pharos Skill Engine's cast send. The CLI sends them on Atlantic with a key, in order, each against its receipt

        Run it yourself
        
        
        cd agent && npm ci
printf 'alice = 0x…\nbob = 0x…\n' > contacts.txt
node dist/src/cli.js pay "Pay alice 25 USDC and send 0.01 PROS to bob for lunch" --contacts contacts.txt --proof flow.json
node dist/src/cli.js pay "Split 2 USDC between alice and bob" --contacts contacts.txt --network atlantic-testnet --execute
node dist/src/cli.js verify flow.json
        
        
        The verifier reads the request again and replays the recorded Chain MCP answers through the same code: the same calls give exactly the recorded payments, totals and verdict, and each sent transaction must be exactly its dry-run one, signed by the sender, in order. No language model reads the request: a request the grammar does not read whole is refused, never guessed at.
