    Falling · 3 observations · every 10 blocks

    Whose USDC balance is watched. Its observations are kept apart from any other holder's.

    1 to 1,000. A run sooner records nothing.

    The example holder is a public address seen moving USDC on Pharos Mainnet in Task 02's live proof; it trades every few blocks, so its balance moves. The observations are kept in this browser; each run adds one, read through Chain MCP. When the trend holds, the watcher prepares a 100 USDC top-up from the example recipient and simulates it. Nothing is signed or sent from this page.

    Proof & technical details

    How it watches

    1. 1get_chain_infoConfirms Pharos Mainnet, chain 1672
    2. 2get_block_number · get_blockPins the newest block. Too soon after the last observation, the run records nothing
    3. 3eth_callReads USDC's decimals and the holder's balance at that block: one observation, added to the store
    4. 4trendJudged over the last observations made since the watcher last acted, so one trend is acted on once
    5. 5eth_call · estimate_gasWhen it holds: the top-up, dry-run at the same block (Task 08)
    6. 6send_raw_transactionNever from here: the hosted Chain MCP is read-only. On Atlantic the CLI sends the action with --execute

    Run it yourself
    
        
    cd agent && npm ci
node dist/src/cli.js watch --store store.json --proof run-1.json
node dist/src/cli.js watch --store store.json --proof run-2.json
node dist/src/cli.js verify run-1.json run-2.json
    
        
    Each run reads one observation and adds it to the store file. The verifier replays each run's recorded Chain MCP answers through the same code, and checks the runs as one history: each must start from exactly the store the run before it left. A watcher is a JSON file: a token or native balance, a view call, the gas price or a nonce; falling, rising, a change in percent or a threshold held.
