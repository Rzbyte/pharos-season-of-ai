      Its transfers and approvals of every official token.

      Each digest covers whole UTC hours, plus the hour so far. The page reads at most 20,000 blocks, so it goes no further than 5 hours; a day or a week is more than one request reads. The CLI makes those, and with a store it digests each completed period once, for a schedule. The example wallet is the address that moved the most USDC in Task 02's live proof, picked from real activity, not known to be anyone in particular. Nothing is signed or sent from this page.

      Proof & technical details

      How it reads

      1. 1get_blockEach hour's first block, by interpolating on the chain's own block times, each search starting where the last ended
      2. 2get_logsA token's every Transfer, one query per 1,000 blocks; or a wallet's transfers and approvals over every official token, two
      3. 3eth_call · get_balanceNow, at the newest block: the token's total supply, or the wallet's holdings. No state is read in the past
      4. 4digestEach hour's figures, against the hour before, written as sentences from those values; no language model

      Run it yourself
      
        
      cd agent && npm ci
node dist/src/cli.js digest usdc --every day --periods 2 --proof digest.json
node dist/src/cli.js digest 0x… --every week --store weekly.json
node dist/src/cli.js verify digest.json
      
        
      The verifier replays the recorded Chain MCP answers through the same code: the same calls give exactly the recorded figures and sentences, the only state read at the newest block, and every get_logs call inside the blocks it says it read. Runs with one store verify as one history: each period digested once. A week of a token is about 480 get_logs calls, paced under the hosted endpoint's 120 a minute.
