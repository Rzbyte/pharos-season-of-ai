10Batch Executor

Bundle a batch

Independent actions in one optimized flow, via Pharos Chain MCP

One action a line: "send 25 USDC to 0x…", "approve 100 USDC for 0x…", "revoke USDC for 0x…" or "wrap 0.5 PROS"; "#" starts a note. At most 6 here. Ctrl+Enter plans it.

Signs every action. Empty: the example sender.

Merged, two sends of one asset to one address are one transaction.

          How it runs
          
          
            
            
          1. 1readEvery line of the batch, or a refusal that names the line: sends of PROS or an official token, approvals and revokes, wraps; nothing is asked of the chain before
            2. 
            
          2. 2mergeSends of one asset to one address become one transaction; two approvals of one allowance are not a batch, since the one sent last wins
            3. 
            
          3. 3dry-runTask 08's dry run of each transaction at one block, every read they share made once: the chain, the block, a token, the sender's balances, the fee quote
            4. 
            
          4. 4proveIndependent only if every balance covers all the batch takes from it before anything it adds, so any order works; one that would revert alone is left out, and the rest do not depend on it
            5. 
            
          5. 5planOne nonce sequence and one fee quote for all, the transactions to sign in order, and the calls saved, counted; at most 10, one transaction each, as the Pharos Skill Engine's batch transfer sends them without a contract
            6. 
            
          6. 6sendOn Atlantic, the CLI signs them and sends them back to back through send_raw_transaction, awaits the receipts together, and checks every value the batch changed
            7.

          Run it yourself
          
        
          cd agent && npm ci
node dist/src/cli.js batch --proof batch-mainnet.json
node dist/src/cli.js verify batch-mainnet.json
# your own batch, one action a line, from a file or standard input:
node dist/src/cli.js batch batch.txt --from 0x...
# on Atlantic, sent back to back with your testnet key:
PRIVATE_KEY=0x... node dist/src/cli.js batch batch.txt --network atlantic-testnet --execute --proof batch-atlantic.json
          
        
          The verifier replays the recorded Chain MCP answers through the same code, shared reads and all: it must ask exactly the recorded questions and come to exactly the recorded plan, independence checks, savings and verdict. A batch sent on Atlantic is also checked transaction by transaction: each one broadcast is exactly the planned one, at its nonce, signed by the sender, and all were sent before any receipt was asked for.
