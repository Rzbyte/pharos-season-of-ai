    The example is Task 08's: 25 USDC from a public address seen moving USDC on Pharos Mainnet in Task 02's live proof. The lookalike example is made up: the first and last four characters of the address that sender moved USDC with most in the blocks read, around zeros, the way address poisoning copies an address. Until a check finds that address, it copies 0x1F35…c85C, which traded with the sender in Task 02’s live proof. The approval example's spender is an unused address. Nothing is signed or sent from this page.

    Proof & technical details

    How it checks

    1. 1get_code · get_transaction_count · get_balanceThe counterparty at the newest block: a wallet, a contract, or a wallet delegated to a contract (EIP-7702); whether it has ever sent a transaction; what it holds
    2. 2get_logsThe token's transfers by the sender or the counterparty over the last 2,000 blocks, two queries a page: what passed between them, transfers of nothing, and everyone the sender dealt with
    3. 3lookalikeThe same first and last four characters as an address the sender moved tokens with (transfers of nothing do not count), but a different address: address poisoning
    4. 4eth_call · estimate_gasThe transaction dry-run at the same block (Task 08), and what it does: an approval to a wallet, an unlimited one, tokens sent to a token contract
    5. 5verdictThe worst signal decides: high is do not send, medium is check first, anything else looks fine

    Run it yourself
    
        
    cd agent && npm ci
node dist/src/cli.js risk --to 0x… --amount 25 --proof check.json
node dist/src/cli.js risk erc20-approve --spender 0x… --amount max
node dist/src/cli.js verify check.json
    
        
    The verifier replays the recorded Chain MCP answers through the same code: the same calls give exactly the recorded signals, level and verdict, every read at one block and every get_logs call inside the history it says it read. The CLI reads up to 10,000 blocks of history with --blocks.
